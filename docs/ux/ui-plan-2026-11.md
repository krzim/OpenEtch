# OpenEtch UX plan: small screens, touch, phone, app window

This plan merges the five audits and is checked against the code in the repository's `web/` folder.

Facts from the code that the plan relies on:
- **Tests:** `npm test` is `node --test "src/**/*.test.ts"`. Tests must be pure TypeScript with no DOM.
- **Dependencies:** react and react-dom only.
- **Proxy:** `vite.config.ts` hard-codes its proxy to `http://127.0.0.1:7878`. Builders must not use it as it is (see Stage A).
- **Locales:** they are spread from per-area files into `locales/en.ts` and `es.ts`.
- **Workspace hotkeys:** they live in `workspace/hotkeys.ts`. `Ctrl+K` is taken (Trim), F11 is RESERVED, and `laser.stop` is `Ctrl+Pause`/`Ctrl+Cancel`.

Items marked **[OWNER DECISION]** need the owner's call. Each one has a recommended default, so builders are not blocked.

## 1. Design spec

### 1.1 Layout modes (replaces the single `NARROW_QUERY` in App.tsx:106)

A new module, `web/src/workspace/layoutMode.ts`, has a pure `resolveLayout({w, h, coarse, override})` and a `useLayoutMode()` external store built like prefs.ts. It writes three attributes on `<html>`:
- `data-layout`: `wide` | `compact` | `tablet` | `phone`
- `data-pointer`: `fine` | `coarse`
- `data-density`: `comfortable` | `compact` | `touch`

All CSS keys off these attributes. The `.narrow` class and the scattered 480/560/600/640/760/900 rules are removed.

| Mode | Rule (first match wins) | Test viewports |
|---|---|---|
| phone | w < 600, or coarse and min(w,h) < 500 | 390x844 |
| tablet | w < 1100, or a coarse pointer at any width | 1024x768, 820x1180 (and real iPads) |
| compact | w < 1600, or h < 900 | 1280x800, 1440x900, 1280x720 (Safari on a MacBook) |
| wide | everything else | 1920x1080 |

Density follows the pointer (`coarse` gives `touch`). Otherwise `compact` and `tablet` get `compact` and `wide` gets `comfortable`. Preferences > Appearance gains Layout (Auto/Wide/Compact/Tablet/Phone) and Density (Auto/Comfortable/Compact/Touch) overrides.

Reviewer note: the browser pane emulates touch only below 768 px wide. At 1024x768 and 820x1180 the pointer stays fine, so the reviewer also sets Density = Touch to check coarse sizing.

**Context strip.** This replaces the numeric bar row (NumericBar.tsx), as in Fusion. Each state fills the same single row and never wraps:
- With a selection: X / Y / W / H / rotation, the lock and the anchor.
- With a tool active: the tool's option bar (`et-bar`, the Text "New text" bar), through a portal slot. The bars no longer float over the canvas (V16).
- Otherwise: the tool hint text.

The unit toggle moves to the status bar only. `.numeric-sep { flex: 1 }` is replaced by `margin-left: auto` (L5). Inputs get a minimum width of 7ch, `tabular-nums` and aria-labels "X", "Y" and so on (V11).

**Top bar.** STOP sits in a `.topbar-stop` slot (`flex: none`) and is never clipped. It never goes into an overflow menu or a sheet.
- The workspace switcher keeps its content width. On tablet and phone it becomes two icon segments of at least 44 px each.
- The brand, project name and doc tabs are what shrinks.
- At compact width and below, Window, Help, theme and Preferences fold into one `⋯` menu. Undo and redo stay in the top bar except on phones, where they move to the canvas HUD.
- A machine status chip sits immediately left of STOP in every mode. On phones it is just a dot.
- STOP gets `z-index: var(--z-stop)`, which is above `.modal-backdrop`, menus and toasts. No ancestor may create a stacking context. The `laser.stop` hotkey must work while a modal is open (V5).

**Docks.** `layout.ts` gains `sizes: {left, right, bottom}` and `areaMode: {left|right: 'pinned'|'rail'|'hidden'}`, sanitised and persisted like the rest of the layout.
- **Splitters** use pointer events with `touch-action: none`. Double-click resets the width.
- **Rail mode** is a strip of vertical window titles. Tap or hover opens the area as an overlay (z `--z-drawer`); a pin button docks it again.
- **Auto policy:** if the canvas column would fall below 640 px, rail the left area first, then the right.
- **Re-fit:** when a dock opens or closes, Viewport keeps the view centre (V9).
- **Presets:** the Window menu gains "Layout: Wide / Compact / Touch". The Compact preset puts {Cuts/Layers, Properties} and {Library, Art, Variable text, Docking} into tab groups, and {Laser, Machine} into one tab group in the Laser workspace (V12, L10).
- **No auto-open:** selecting something never opens a drawer (App.tsx:221 is removed). On tablet a floating "Properties" pill opens the drawer; on phone the selection shows the peek sheet.
- **Inert drawers:** closed overlays and drawers get `inert`.

**Focus canvas.** The `view.focusCanvas` action (Window menu and hotkey) hides the docks, the palette and the bottom row. It keeps the top bar with STOP and the context strip, and extends `window.sidePanels`.

**Phone (`PhoneShell`).** Phone is a separate layout that reuses the existing components through slots.
- **Top bar:** `≡` menu, document name, status dot, STOP (fixed width, 64 px or more).
- **Canvas:** full bleed, with a fit/zoom cluster, undo/redo and the touch HUD.
- **Bottom tabs:**
  - **Canvas:** the tool strip and the selection sheet (X/Y/W/H, centre on stock or field, rotate 90, delete).
  - **Layers:** CutsLayers with power, speed and passes, plus the palette.
  - **Job:** the Laser dock with preview stats, Frame / Stop frame, Start or Request run, progress, pause/resume and run history.
  - **More:** File, Import, History (the timeline as a list), Window, Preferences, "Use as an app", and "Desktop features".
- **Off the phone:** node editing, pen and polygon, trim/weld, Docking, the Art library editor, device editing, the lens wizard and the GRBL console. These live under More > Desktop features with a hint.
- **Dialogs** become full-screen sheets at 600 px wide and below.
- **[OWNER DECISION]** Whether Start is offered on the phone at all. Recommended: yes. It is still "Start in the app" and stays gated by approval and the checklist.

### 1.2 Touch interaction model

The rule is: **one finger is the left mouse button, two fingers move the view.** Mouse behaviour stays exactly as it is in LightBurn.
- **Tolerances per event** come from `pointerClass(e)` and `TOL[class]` in pointer.ts. On touch: click 14, slop 10, node 18, snap 14, handle hit 44, double-tap 24 px / 400 ms, long-press 500 ms. Pen uses 8/6/10/10/24.
- **Handles:** on touch they are drawn at about 2x. When the selection is small on screen, they are placed outside its bounds.
- **Tap on a selected object** switches between scale and rotate handles (LightBurn's click-again rotate).
- **Gesture arbiter:** a pure state machine in `web/src/touch/gesture.ts`.
  - The first finger opens a *pending* press and nothing is committed on down.
  - A second finger within slop or 150 ms drops the press without side effects and starts pan/pinch. This fixes the stray Line vertex, the measure point and Trim-on-pinch (T4).
  - A second finger during a drag cancels the drag (the touch Esc).
  - Line, measure, pick and Trim commit on lift. Trim highlights the piece while the finger is down.
- **One finger on empty space draws a marquee:** left to right encloses, right to left crosses, same styles as the mouse. The Preferences option "One finger on empty canvas: Select (default) / Pan" keeps the old behaviour.
- **Long-press** (500 ms within slop, no second finger) opens the same context menu as right-click, after selecting the object under the finger. A ring animation shows it coming. It works on the canvas, tree and layer rows, timeline chips, and art and library items. Rows and chips also get a visible `⋯` button.
- **Modifier bar** (`TouchHud`, coarse pointers only, bottom-left of the canvas). It holds context toggles:
  - Select: Add, Toggle, Constrain, No snap.
  - Rect/Ellipse: Square, From centre, No snap.
  - Line/Pen: 15° steps.
  - While rotating: Fine steps.
  - Node: Add.

  A tap latches the toggle for the next gesture; a double-tap locks it. The bar feeds a `virtualMods` store that `modsOf()` ORs with the physical keys. Mid-drag changes replay through the existing `modifierReplay` path.
- **Selection action bar** (touch; optional on desktop). A pill above the selection with Copy, Paste, Duplicate, Delete, Group/Ungroup, Rotate 90, Flip and `⋯` (the full menu). On a coarse pointer the Properties position section gets a nudge pad.
- **Pencil:** while a pen is down, and for 1 s after, touches only navigate (palm rejection). A two-finger tap undoes and a three-finger tap redoes.
- **MacBook:**
  - The pan-or-zoom decision is latched per wheel stream (150 ms idle), so it never flips mid-swipe.
  - "Trackpad: scroll pans, pinch zooms" is on by default on Mac.
  - Space+drag pans; Shift+wheel pans horizontally.
  - Safari's `gesturestart`/`gesturechange` are handled.
  - Cmd stands for Ctrl on Apple platforms, and Ctrl+click stays the Mac right-click. A `contextmenu` during an active gesture is ignored.
  - Shortcut hints show ⌘ ⌥ ⇧ on Mac.
- **Global CSS:**
  - `html { touch-action: manipulation }`.
  - `.app { user-select: none; -webkit-touch-callout: none }`, re-enabled for input, textarea and contenteditable.
  - Hover visuals sit inside `@media (hover: hover)`, plus `:active` states.
  - Under `(pointer: coarse)`, `input, select, textarea { font-size: max(16px, 1em) }`.
  - Ctrl+wheel and gesture events outside the canvas are blocked. Ctrl/Cmd with `=`, `-` or `0` always uses `preventDefault`, so the page never zooms.
- **Number entry:** signed fields (X/Y, rotation, offsets) use `inputMode="text"` and `enterKeyHint="done"`. On coarse pointers power, speed, passes, frequency and size get −/+ steppers with press-and-hold.

### 1.3 Full screen and the installable app window

1. **Full-screen toggle.** The `view.fullscreen` action appears as a top-bar icon, in the Window menu and in command search. The default key is `Alt+Enter` (rebindable); F11 stays the browser's.
   - It uses `documentElement.requestFullscreen({navigationUI:'hide'})`, with `webkit` fallbacks. State syncs from `fullscreenchange` and `(display-mode: fullscreen)`, which also covers the case where F11 owns full screen ("press F11 to exit").
   - The toggle is hidden when `fullscreenEnabled` is false (iPhone, iOS Home Screen apps).
   - Chromium on a secure origin also locks Esc with `navigator.keyboard.lock(['Escape'])`. Elsewhere a one-time tip says "Esc leaves full screen; Alt+Enter toggles". This works over plain http today.
2. **Manifest and metas.** `web/public/manifest.webmanifest` has:
   - name and short_name `OpenEtch`, `id/start_url/scope "/"`
   - `display: standalone` and `display_override: ["window-controls-overlay","standalone","minimal-ui"]`
   - theme and background colour `#23262a`
   - icons: 192, 512, a maskable 512 and an SVG

   `index.html` adds:
   - the manifest link, the SVG icon and a 32 px PNG favicon, and a 180 px apple-touch-icon
   - `theme-color` twice (light and dark media)
   - `color-scheme`, `mobile-web-app-capable`, `apple-mobile-web-app-title`
   - `apple-mobile-web-app-status-bar-style=black-translucent`, together with top safe-area padding on `.topbar`

   For window-controls-overlay, `.topbar` uses `env(titlebar-area-*)` with `app-region: drag` on empty space and `no-drag` on controls. `document.title` becomes `<doc> • — OpenEtch` when dirty.
3. **Plain http works today for:** Safari's File > Add to Dock (macOS 17+), Add to Home Screen on iPad and iPhone, Chrome/Edge's Create shortcut > Open as window, and the Fullscreen API.
   - A "Use as an app" dialog (Help menu, and once on the first touch visit) detects the platform and display mode and shows the right steps. It hides itself when the app already runs standalone.
4. **Persistent token is required for app windows.** Dock apps and Home Screen apps do not see Safari's localStorage, and the engine makes a new token on every restart.
   - The engine stores the token in `<config-dir>/access-token` (mode 0600) and adds `openetch token [--rotate]`, which prints the token and a pairing URL.
   - The web app shows a "Connect to OpenEtch" card on 401 or when no token is stored.
   - [OWNER DECISION] Also set an HttpOnly, SameSite=Strict cookie when `?token=` is accepted. Recommended: yes, so Add to Dock arrives already logged in.
5. **HTTPS: does the engine need it?** Not to ship this plan. HTTPS is needed only for Chrome/Edge install, window-controls-overlay, Wake Lock during burns, the browser camera, Keyboard Lock and service workers. [OWNER DECISION] Which route; recommended order:
   - **(a) Tailscale.** No engine code. On the Pi:
     - `sudo tailscale up`
     - `sudo tailscale serve --bg --https=443 http://127.0.0.1:7878`
     - Open `https://<pi-name>.<tailnet>.ts.net` on each device with the Tailscale app running.
     - Start the engine with `--allow-host <pi-name>.<tailnet>.ts.net` and keep the persistent token.
   - **(b) Caddy with a local CA.** Caddyfile: `<pi-name>.local, <pi-ip> { tls internal  reverse_proxy 127.0.0.1:7878 }`.
     - Install the root CA once on each device: macOS Keychain set to Always Trust; Windows Trusted Root; iOS/iPadOS profile, then Settings > General > About > Certificate Trust Settings.
     - The root CA file is at `/var/lib/caddy/.local/share/caddy/pki/authorities/local/root.crt`.
     - The engine then listens on 127.0.0.1 and must run with the new `--require-token`, because loopback otherwise turns the token off. Add `--allow-host <pi-name>.local`.
   - **(c) Later:** engine-native `--tls-cert/--tls-key` (rustls), optionally with a built-in CA and a one-tap profile at `/ca`.
   - **Stopgap for a single computer in Chrome/Edge:** set `chrome://flags` "Insecure origins treated as secure" to `http://<pi-ip>:7878`.
   - A plain self-signed certificate that users click through is not an option.
6. **Engine static serving.** These matter most for app windows, which have no reload button:
   - Fall back to `index.html` only for navigations. Missing `/assets/*`, `favicon.ico` and the manifest return 404.
   - `index.html`, the manifest and `sw.js` get `Cache-Control: no-cache`; `/assets/*` gets `public, max-age=31536000, immutable`.
   - Serve precompressed `.br`/`.gz` files written at build time. The JS bundle is 1.15 MB uncompressed today.

### 1.5 Accessibility baseline (WCAG 2.2 AA)

- **Contrast:** text 4.5:1, UI components and borders 3:1, enforced by a unit test over the token pairs in both themes.
- **Target size:** at least 24x24 px on fine pointers (2.5.8) and at least 44x44 on coarse. Canvas handles hit at 44 on touch.
- **Focus:** the `:focus-visible` ring `0 0 0 2px var(--panel), 0 0 0 4px var(--accent)` on button, `[role=menuitem]`, `[role=treeitem]`, input and select. No `outline:0` without a replacement.
- **Menus:** `role=menu`, roving focus, arrows, Home/End and type-ahead; focus goes to the first item on open; Esc closes only the menu and stops propagation (V14).
- **Dialogs:**
  - one stack, so Esc and Enter reach only the top dialog
  - focus trap, initial focus and focus restore; `aria-labelledby`
  - backdrop dismissal on click (same target at down and up), and only for non-form dialogs
  - translated Close label
- **Live regions:** machine errors are `role=alert` and stay until dismissed. Info toasts are `role=status`. Toasts are real buttons with optional actions.
- **No hover-only information:** timeline details, disabled reasons and the "needs HTTPS" camera note appear inline or in a popover.
- `prefers-reduced-motion` is respected by the sheets, the long-press ring and the status-chip pulse.
- All numeric fields have accessible names.

## 2. Work packages

**Rules for every builder:**
- Work only in your own branch or worktree, never on the main checkout. Never run anything against a real machine or an engine someone is using; test only against a simulator engine.
- Run your own simulator engine from your worktree with the same flags as the audit simulator, on your own port (P1 7981, P2 7982, P3 7983, P4 7984, P5 7985). Either point Vite at it (`OPENETCH_ENGINE=http://127.0.0.1:798N npm run dev`, from Stage A) or `npm run build` and start the engine with `--web-dir <worktree>/web/dist`.
- No UI library and no new runtime dependency.
- Each package puts its new CSS in its own new CSS file. Existing CSS files are owned as listed: `styles.css` and `workspace.css` by P1, `edit.css` by P3, `job.css` by P5. Every other existing CSS file is frozen; override from your own file.
- New strings go only in your package's locale stub (`en-<pkg>.ts` / `es-<pkg>.ts`).
- Before merging: `npm run typecheck`, `npm test`, and `npm run build` must pass.
